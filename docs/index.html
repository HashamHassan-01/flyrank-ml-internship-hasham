ML CAPSTONE — CONTENT PRIORITIZATION

Content Refresh Prioritization Using Observable Search Signals

A reproducible decision-support workflow for ranking content pages for human refresh review using search volume, content age, average search position, and click-through rate.

Anonymized FlyRank internship dataset · 30,000 pages · Client-grouped validation

1. Abstract

Content teams cannot manually inspect every page with the same level of attention. This project investigates whether observable content and search-performance signals can help prioritize pages for content-refresh review.

The workflow uses an anonymized dataset containing 30,000 content pages and 44 fields. Four observable signals are used for modeling: search volume, content age, average search position, and click-through rate (CTR).

A transparent Opportunity Score was constructed using fixed weights for these signals. A Random Forest Regressor was then evaluated using a client-grouped train/test split so that pages belonging to the same client could not appear in both training and testing data.

The Random Forest achieved an MAE of 0.002149, RMSE of 0.006581, and R² of 0.987601 on the grouped test set. However, the Opportunity Score itself is calculated from the same four features used by the model. Therefore, these results demonstrate that the model can reproduce the constructed scoring rule rather than proving that it predicts an independent business outcome.

Key conclusion: The workflow is best treated as a decision-support system that creates a ranked human-review queue. Independent post-refresh outcome data would be required to determine whether the recommendations lead to real-world SEO improvement.

2. Question

Research Question

Which observable content and search signals can help prioritize pages for content-refresh review?

Problem Statement

Content teams need a practical way to decide which pages deserve attention first. Reviewing every page equally is inefficient, so the goal of this project is to create a reproducible workflow that ranks pages according to observable signals.

The workflow focuses on search demand, content age, average search position, and CTR. It is designed to support human review rather than automatically decide which pages should be refreshed.

Decision-support goal: Rank pages for human review and explain why a page receives a higher priority.

The project does not attempt to prove that refreshing a page causes improved SEO performance.

4. Methodology

Feature Set

The model uses four observable features:

  • search_volume
  • content_age_days
  • avg_position
  • ctr

Opportunity Score

A rule-based Opportunity Score was created using normalized versions of the four signals.

volume_score = search_volume / max(search_volume) age_score = content_age_days / max(content_age_days) rank_score = avg_position / max(avg_position) ctr_score = 1 - (ctr / max(ctr)) Opportunity Score = 0.40 × volume_score + 0.25 × rank_score + 0.20 × age_score + 0.15 × ctr_score

The weighting gives the largest contribution to search volume, followed by average position, content age, and CTR.

Model

A Random Forest Regressor was selected to reproduce the Opportunity Score from the same four input signals.

The model used 100 trees with a fixed random state of 42.

Grouped Validation

A GroupShuffleSplit was used with client_id as the grouping variable. This prevents pages from the same client from appearing in both the training and test sets.

Validation check: 21,741 rows were used for training and 5,335 rows were used for testing. The training set contained 24 clients and the test set contained 7 clients, with zero client overlap.

Leakage / Target Definition Check

The most important methodological limitation is that the target is constructed directly from the same four features used by the model. This means the machine-learning task is primarily a reproduction task rather than prediction of an independently measured outcome.

Signal Findings

The signal audit produced several directional findings that can be used to support the review workflow.

  • The oldest 25% of pages had a median CTR of 0.05, compared with 0.08 for the remaining pages. The measured difference was -0.03.
  • After excluding avg_position = 0 records, CTR and average position showed a negative Spearman relationship of rho = -0.2342.
  • Search volume had a weak negative association with CTR, with Spearman rho = -0.0756. This signal was therefore treated as mixed rather than as a standalone rule.

These findings are directional associations and should not be interpreted as causal effects.

6. Limitations

The analysis has several important limitations that affect how the results should be interpreted.

  1. Constructed target: The Opportunity Score is derived from the same four features used by the Random Forest.
  2. No causal claim: Observational relationships do not establish that refreshing a page will cause better search performance.
  3. Missing position data: avg_position = 0 represents missing position data and was excluded from the modeling workflow.
  4. Missing values: Rows with missing required modeling features were excluded.
  5. Decision support only: The model should not automatically approve or reject content refreshes.
  6. Independent validation required: Post-refresh performance outcomes are needed to determine whether the prioritization approach produces real-world improvement.
The correct interpretation is therefore: this workflow helps organize human review; it does not guarantee SEO improvement.

7. Ranked Recommendations

The recommendations below convert the observed signals into a practical content-review workflow.

1. Prioritize older pages with lower CTR

Evidence: The oldest 25% of pages had a median CTR of 0.05 compared with 0.08 for the remaining pages.

Action: Review older pages with weaker observed CTR first. Check whether the content is outdated, mismatched to search intent, or otherwise in need of improvement.

2. Give additional attention to lower-CTR pages with weaker search position

Evidence: CTR and average position showed a negative Spearman relationship of rho = -0.2342 after excluding records without valid position data.

Action: Use lower CTR together with weaker search position as a combined review signal rather than relying on either metric alone.

3. Treat search volume as a secondary signal

Evidence: Search volume had only a weak negative association with CTR, with Spearman rho = -0.0756.

Action: Do not automatically prioritize a page only because it has high search volume. Use search volume alongside other signals and human review.

Human-Review Rule

Every recommendation should be treated as a review prompt rather than an automatic decision. A content reviewer should inspect the page, search context, content quality, and business relevance before approving a refresh.
